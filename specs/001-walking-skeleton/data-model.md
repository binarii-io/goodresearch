# Data model — 001 walking skeleton

Two modules are involved (see [context map](../../docs/domain/context-map.md)):

- **workspace** (generic subdomain): accounts, members, teams, memberships, access events. Authentication itself (OpenID Connect flow, sessions, provider identities) is delegated to the auth library, which owns its tables (see [research.md](research.md#r2-authentication)). There are no passwords.
- **research** (core subdomain): projects.

IDs are UUIDv7 generated by the app, typed as branded strings (`AccountId`, `TeamId`, `ProjectId`…). Times are `timestamptz` (UTC). Tables are prefixed by their module.

### Account (aggregate root)

Extends the auth library's `user` record with domain fields; the domain only sees the projection below.

| Field | Type | Rules |
|---|---|---|
| id | AccountId | = auth user id |
| name | string | 1–120 chars (provider name, else email local part, truncated); `null` once deleted |
| email | string | unique (case-insensitive) among non-deleted accounts; `null` once deleted |
| language | `'en' \| 'fr'` | at creation from the `Accept-Language` header, else `en`; then set by the user (FR-024, FR-025) |
| role | `'admin' \| 'member'` | `admin` if the email is in `ADMIN_EMAILS` at creation, else `member` (FR-005, FR-006, FR-010) |
| status | `'active' \| 'deactivated' \| 'deleted'` | see state machine |
| lastSignInAt | timestamp? | updated on each sign-in |
| version | integer | optimistic concurrency |

State machine:

```
active ──deactivate──▶ deactivated ──reactivate──▶ active
  │                         │
  └────────delete───────────┴──▶ deleted (terminal: name/email erased, sessions revoked)
```

Invariants (enforced by the aggregate, tested first):

- A command that would leave the workspace with **zero active admins** fails with `LAST_ADMIN` (demote, deactivate, delete).
- `deleted` is terminal: no command applies to a deleted account (`ACCOUNT_DELETED`).
- Deleting erases `name` and `email` and removes role privileges and memberships (FR-014b).
- Every state, role or membership change records an **AccessEvent** in the same transaction.

### TeamMembership

| Field | Type | Rules |
|---|---|---|
| teamId | TeamId | |
| accountId | AccountId | |
| grantedAt | timestamp | |
| grantedBy | AccountId | |

Primary key `(teamId, accountId)`. Owned by the **Account** aggregate (memberships are part of an account's access), so granting/removing a membership is one aggregate change + one access event. Deleting a team removes its memberships (cascade, recorded as access events).

### AccessEvent (append-only)

| Field | Type | Rules |
|---|---|---|
| id | AccessEventId | |
| occurredAt | timestamp | |
| actorId | AccountId? | `null` for system events (e.g. provider sign-up) |
| subjectId | AccountId | the affected account |
| type | `'account_created' \| 'role_changed' \| 'membership_granted' \| 'membership_removed' \| 'deactivated' \| 'reactivated' \| 'deleted'` | |
| details | JSON | e.g. `{ from: 'member', to: 'admin' }`, `{ teamId, teamName }` (team name copied: history stays readable after a team is renamed or deleted) |

No update or delete path in the app (FR-014a). After an account deletion, events keep referencing the anonymised account.

### Access rules (policy, pure function)

```
canAccessTeam(account, teamId)   = account.status = active ∧ (account.role = admin ∨ teamId ∈ account.teamIds)
canManageWorkspace(account)      = account.status = active ∧ account.role = admin
```

Exposed through the workspace public API as `getAccessContext(accountId) → { role, teamIds }`, consumed by other modules' handlers and queries.

## research

### Project (aggregate root)

| Field | Type | Rules |
|---|---|---|
| id | ProjectId | |
| teamId | TeamId | required (FR-015); referenced by ID only |
| name | string | 1–120 chars after trim (FR-016) |
| goal | string | 0–10,000 chars, line breaks preserved |
| createdBy | AccountId | |
| createdAt, updatedAt | timestamp | `updatedAt` changes only with name/goal/team |
| version | integer | stale version → `VERSION_CONFLICT` (FR-020) |

Commands: `create-project`, `rename-project`, `update-project-goal`, `move-project-to-team`. Each handler first checks `canAccessTeam` for the project's current team (and the target team for a move); a project outside access is reported as `PROJECT_NOT_FOUND` (FR-012).

Queries: `list-projects(accessContext, teamFilter?)` (sorted by `updatedAt desc`), `get-project(accessContext, id)`, `count-projects-by-team(teamId)` (public, for team deletion).

## Cross-module rules

- research → workspace: `getAccessContext`, team names for display (query API).
- workspace → research: `countProjectsByTeam` (query API) before deleting a team.
- No foreign-key joins across modules in queries; a DB foreign key `research_projects.team_id → workspace_teams.id` (`ON DELETE RESTRICT`) protects integrity only.

## Validation summary (from the spec)

| Rule | Where |
|---|---|
| Name lengths, trims, goal length | contracts (Zod) + aggregates |
| Team name unique (case/space-insensitive) | Team aggregate + unique index on `nameKey` |
| Last admin protection | Account aggregate (needs active-admin count from repository) |
| Provider sign-in: verified (or trusted) email, initial admins, allow-list | pure `SignInPolicy` in the workspace domain, called from the auth library's `validateUserInfo` hook before any account is created |
| Optimistic concurrency | repositories (`WHERE version = ?`) |
