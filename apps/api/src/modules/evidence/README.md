# evidence

The Analysis phase of an interview study (spec 012, context map #6 Evidence): each validated interview cut into **verbatims**, then **facts** a person decides.

- **Text analysed** (`AnalysisSources.analysedText`, computed by `transcripts`): the study setting `with-corrections` (default, corrections not rejected applied) or `clean-only` (the latest validated clean version). Evidence never reads corrections or another module's tables; every source is a port wired in `compose.ts`.
- **Find facts** (`application/commands/analysis-commands.ts`, queue `evidence.facts`, one run per study, never with a lexicon reading or a cleaning): imports the missing transcripts, then per interview (3 at once):
  1. the **verbatim pass** reads the text in chunks of 60 turns with 5 of context (`makeChunks` in `@goodresearch/shared`), known names and speaker labels as placeholders (labels naming a role, "Interviewer", "Speaker 2", stay: `isGenericLabel`), each turn sent with its speaker's role only; `domain/verbatims.ts` `checkVerbatims` keeps an excerpt only when it is in a new turn of an interviewee, found word for word (case, spaces, apostrophes ignored), 3–120 words, not cutting a placeholder;
  2. the **fact pass** groups the verbatims (batches of 150) into facts: statement in English and French, polarity, theme (`s1`… or `other`), verbatim ids; `domain/facts.ts` `checkFacts` drops unknown ids, unknown themes, names and placeholders, and `isReproposal` drops a fact already decided (same verbatims, or 60% of the words of its statement). At most 80 facts are kept per batch, cut by the app: the answer schema has no `maxItems`, which Vertex rejects as too complex with the nested list of ids (400 `INVALID_ARGUMENT`).
  One interview can be taken out until its own reading ends (`domain/analysis-run.ts` `canStopFacts`, `stopped_sessions`): the worker checks before each part and each fact batch, and once more after saving the interview done but before writing its reading, so nothing of that reading is kept for it (`STOPPED`). `requestSessionStop` appends only if the interview's reading is still open, in the same statement, so a take-out after that save is refused (`TOO_LATE_TO_STOP`). An interview taken out before the job starts is not even imported; a second take-out gives the same answer; an interrupted run keeps it `STOPPED`. The overview shows it stopped at once (`withFactsStops`).
  A new reading keeps decided facts and their verbatims, replaces the proposed ones, never brings back a verbatim set aside (`replaceReading`, one transaction).
- **Decisions** (`commands/fact-commands.ts`): accept, edit, reject with the version seen; accept all shown; a person's fact (accepted at once) from verbatims; a verbatim from highlighted text in an interviewee's turn, possibly added to a fact without deciding it (`attachVerbatim`), or one narrowed to the words a person selects in it (`resizeVerbatim`: same id and facts, origin `person`); set aside; a speaker label attributed to an interviewee or to the interviewers (`domain/speakers.ts`). A fact whose speaker is unknown cannot be accepted (`SPEAKER_TO_ATTRIBUTE`). A verbatim added to a fact is saved with the fact in one transaction (a fact changed meanwhile leaves no verbatim behind), and a label attributed to the interviewers sets its verbatims aside in the same transaction as the attribution. "Accept all shown" reads the study, its known names and each interview's verbatims once. A statement written in one language is translated into the other by the queue `evidence.translate`, while those words are still the fact's (`not-translated` on failure, retried on request).
- **State** (`domain/analysis-state.ts`, derived at each read): verbatims are found again in the current text (`reanchor`); a lost verbatim, a re-imported transcript or a changed setting or anonymisation asks to analyse again — a word corrected in Cleaning does not.
- Ledger: tasks `fact-verbatims`, `facts`, `fact-translation`; refs `facts:<runId>:<sessionId>` and `facts-translation:<sessionId>`; the costs are shown per interview and for the study, whoever ran them. Consent: `evidence_consents` (asked again when the provider changes).
- Tables (migration `0028_interview_facts.sql`): `evidence_runs`, `evidence_readings`, `evidence_verbatims`, `evidence_facts`, `evidence_fact_verbatims`, `evidence_speakers`, `evidence_consents`; cascade with the session and the study.
